# 性能记录

## 0.7.0：静态主题橱窗

每主题只保存一张最大192像素的arrow首帧封面；以原图摘要复用或失效，图片继续使用64MB上限的NSCache。LazyVGrid只按可见卡片请求缺失缓存，升级旧索引不在SwiftUI body内解码整套动画。没有悬停播放、动画时钟或周期性卡片刷新；返回橱窗会卸载编辑预览。本轮未修改光标运行层，也未重新测量整机功耗，不能据此承诺具体节能比例。


## 0.5.4：文字注册身份与素材选项

文字动画去掉每帧额外的自定义 NSCursor 提交，保留系统文字资源身份；用户确认所测第三方应用场景闪烁改善。素材备选仅在编辑或导入时处理，运行层仍只准备当前选中素材，不同时运行多套动画。Dock 所属窗口只在按下时查询，不增加移动路径轮询。

本机受控短测静态 0.42% / 4 秒20 tick，文字动画 8.06% / 107次提交。测量包括后来撤除的地址栏角色保持试验，不作为最终包节能幅度的保证；不含 WindowServer 或整机耗电。地址栏问题按用户要求搁置；最终收尾不再运行全局光标测试，以免干扰原生行为对照。

## 0.5.3：文字同帧交接与输入去重

2026-10-28，本机 release 受控检查。静态约 0.51%（4 秒20 tick）；持续文字动画约8.64%，实际94次提交。文字采样期间每1/60秒固定测试角色，避免前台应用更换光标后动画停住造成虚假的低CPU结果。计时包含该受控角色请求，不包含 WindowServer 或整机功耗。

文字角色需要同步系统当前静态帧以消除移动重选时的闪烁；这增加了持续动画开销。资源预热与有界缓存避免运行时重复编码，只传输已连接屏幕所需的分辨率。静态路径继续低频检查。输入监听与计数信用去重移除了原先额外两秒的高频尾巴。Finder剩余抽动已按用户要求暂缓；不将受控时序通过等同于真实拖放已修好。

## 0.5.2：调整角色交还系统与缩放收尾

2026-10-28，已停止旧 Gallery 实例后在同机 release 测试程序短测：静态约 0.50%（4 秒 21 次 tick），示例光标主题 文字多帧常态约 3.07%（3 秒）。这不是整机能耗，也不是所有机器或应用的固定上限。不要同时运行旧版或其他光标替换进程进行对比。

已正确注册并选中的调整常态直接由系统播放，运行检查验证进入后无 Gallery 动画帧重复提交。系统注册等时采样上限仍为 24 帧，保持总时长。甩动的变化阶段为 60Hz，放大停留阶段直接等待收尾起点，不持续逐帧唤醒；单次缩放结束后停止调度。

若提交返回的编号尚未变化，进行临时图像确认，避免将旧前台资源编号误认成自己。使用有界图像指纹缓存和已有观察队列，正常确认完成后恢复原有调度。

## 0.5.1：重复帧与事件驱动移动

2026-10-28，在相同本地 release 测试程序与 示例光标主题 主题下，旧基线文字多帧常态约 4.16% 自进程 CPU；新版本多次短测约 1.8–3.1%，静态约 0.15–0.56%。每次静态采样 4 秒、文字动画 3 秒，仍是短时回归数值，不能等同于整机功耗或普遍上限。

示例光标主题 文字常态 84 帧中只有 44 个连续图像区间。新增预计算表跳过相邻相同图像的提交，并跨循环尾部/头部合并相同停留；原始帧序、停留时长及总周期不变。位图已解码，提交缓存按图像身份复用。

单纯移动不再触发 120Hz 渲染计时器；事件立即观察变更的角色，原生系统负责位置。缺少事件监听时仍保留输入计数采样。角色独立待机值只覆盖原有状态机的一个截止时间，不新增每角色定时器。

新增运行检查覆盖 1,000 次移动观察不产生高频渲染、重复帧不重复提交且截止时间不变、高分辨率系统箭头从三类调整角色退出，以及待机值隔离。界面检查覆盖重开窗口的 Dock 策略和数值输入。

## 0.5.0：系统光标通道

2026-10-28，本地 macOS 27.2 / Apple Silicon，release 构建，示例光标主题 主题。旧版覆盖窗口已移除，
系统负责鼠标位置，程序只更新缓存图像帧。单帧常态采用系统注册资源或缓存 NSCursor，多帧和交互最多 60 次提交/秒。

`Scripts/runtime-check.sh` 当前使用自己的 AppKit 事件循环和独立恢复记录，不移动鼠标或注入 OS 输入。
CPU 为 getrusage 的进程用户及系统时间差 / 墙钟时间差；不包含 WindowServer、显示器或整机耗电。
预热后静态箭头采样 4 秒，示例光标主题 多帧文字常态采样 3 秒：

| 场景 | 自进程 CPU | 运行检查次数 |
|---|---:|---:|
| 静止箭头 | 0.45% | 4 秒 19 次 |
| 多帧文字常态 | 4.09% | 按动画帧率更新 |

以上是短时回归数值，不能作为所有应用的上限，也不与旧版不同测试程序构成严格功耗对照。
额外检查包括实际系统图像三帧切换、300 次角色切换中的可见性与大小、点按抢占、自身帧过滤及停用恢复。
调度中心模式以状态注入验证；本轮没有自动化真实三指滑动、锁屏或 Dock 长时间悬停。

复测：

```sh
bash Scripts/runtime-check.sh /tmp/gallery-runtime-new /path/to/theme.gallery
bash Scripts/editor-check.sh /tmp/gallery-editor-new
```

不要与正在运行的 Gallery 或其他光标工具并行检查。完成或失败后程序尝试恢复备份。

## 0.4.0 历史记录（旧覆盖窗口实现）

测量时间：2026-10-27。目的为检查同一机器上的回归与优化幅度，不设通用 CPU 保证。

## 方式

0.3.0 的运行层与当时的核心/原生桥单独编译，加入相同的基准循环；0.4.0 使用当前运行层。
均使用同一份 示例光标主题 主题、独立前台原生 NSCursor 测试窗口，以及后台控制器。
启动、主题转换和预热不计入测量；两个控制器均运行同样的 AppKit 事件循环。

- 静止：关闭待机，保持箭头 6 秒。
- 变化：45 次箭头、文字、水平调整切换，每次等待 40 毫秒。
- 点击：30 次直接向状态机提供按下/松手边沿，统计按下处理函数到提交显示帧的耗时。
- 大小：连续更新到 80%、100%、120%、150%、100%，统计总同步耗时。
- CPU：`getrusage(RUSAGE_SELF)` 的用户及系统 CPU 时间差 / 墙钟时间差 × 100。包含控制器自身工作线程和事件循环，不包含前台辅助进程或 WindowServer。

## 结果

| 指标 | 0.3.0 | 0.4.0 |
|---|---:|---:|
| 静止 CPU | 8.85% | 4.85% |
| 角色变化 CPU | 18.66% | 9.77% |
| 点按处理 p95 | 0.968 ms | 0.409 ms |
| 五次大小更新 | 4861.7 ms | 1.95 ms |

大小更新由重新生成并注册所有条带，变为当前图层的几何更新。因此这里比较的既是实现路径变化，
也是用户操作需要同步等待的时间。原生静态资源仍在启用主题时一次性注册；未知与原生角色不缩放。

点击数据不是设备输入到屏幕发光的端到端延迟。拒绝输入监控权限时，还存在最多约一个 120 Hz 采样周期的等待，
以及系统调度和显示器刷新时间。编辑器窗口可见时和其他复杂主题的 CPU 可能不同。

它们会正常退出已运行的 Gallery，使用独立恢复记录并恢复原光标与位置；不要与另一光标工具同时运行。

编辑器检查只使用传入的新目录，不修改用户主题库或登录项。
