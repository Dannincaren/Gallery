# PRTS 1.1.5 资源检查

本次只将用户选定的EXE作为数据读取，未执行Windows程序。安装器269,728,768字节，SHA256 `51934f3a2853132f2eb393debf1303047e882417795a2a024fe6678bfad97747`；包含1,406个CUR/ANI资源，Gallery当前映射为46个系统变体。辅助素材还包括待机进入/退出、逐帧手形和抓取序列，不等于每项都会成为单独的光标角色。素材不上传仓库。

## 已确认

箭头、链接与文字的全新提取结果与此前0.5.4本地原始转换逐帧一致。箭头按下6帧/0.10秒，按住1帧，松手12帧/0.20秒；松手12帧中有10张不同图像，重复的是相邻停留帧，没有第二个完整松手周期。源CUR帧全部96×96，热点(28,20)；Gallery逻辑32×32、热点(9⅓,6⅔)，未发现帧间尺寸/热点改变。

ANI最后一帧的rate=3600 jiffies（60秒）是Windows素材的冻结哨兵；Gallery已有定点去除该长等待的逻辑，转换后保持0.20秒，不会按一分钟循环。每帧有效区块/索引/图像解码和Gallery归档往返均通过。

## 跨阶段共享画面

- 按下2、3 = 松手5。
- 按下4、5 = 按住0 = 松手0。

编号测试所有阶段画面均不同；用户在原速编号主题中暂未发现问题。两者还有135%/185%大小及关闭/开启甩动的变量，因此不能据此断言原素材有错，也不能宣称抽动修复。

当前渲染器会识别历史图像并接续松手进度。相同图像可属于不同阶段与进度，单凭图像匹配不足以证明它就是本次松手的某一帧；需要继续审计阶段、手势起点、提交版本与实际显示之间的关系。源文件检查并不能证明所有系统呈现路径正确。

此前逐帧等待栅栏及修改注册路径的两个候选均未通过用户实际验证，已经留档，0.7.3不包含它们。后续应固定大小/甩动/节奏，再只改变是否共享帧进行对照，避免同时修改多个变量。
